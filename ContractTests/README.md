# Client and backend contract checks

`Client/` compiles and exercises generated proxies against the published browser client, pinned to `@cratis/arc` and `@cratis/arc.react` 22.45.0 and `@cratis/fundamentals` 7.22.0. `Http/` compares HTTP behavior with the [locked .NET fixture](DotNET/README.md). `LegacyDecorators/` and `Typecheck/` protect decorator consumption.

## Compare proxy generators

`ProxyComparison/` pairs `DotNET/ProxyComparison/Fixtures.cs` with `ProxyComparison/TypeScript/Fixtures.ts`: a `Register` command, `Listing.All` snapshot query, `Listing.Observe` observable query, a nested `Detail` with GUID/date fields, `Notice`/`UrgentNotice` inheritance, a numeric `Status` enum, and portable not-empty, maximum-length and minimum-value validation rules with custom messages.

From the repository root, with Node/Yarn and the .NET fixture's prerequisites installed:

```sh
yarn install --immutable
yarn build
dotnet restore ContractTests/DotNET/HttpFixture.csproj --locked-mode
dotnet build ContractTests/DotNET/HttpFixture.csproj -c Debug --no-restore
yarn test:proxy-comparison
```

Always rebuild after changing C# fixtures. `yarn test:conformance` performs the locked restore and builds before running the HTTP checks and this full comparison. `yarn ci` stays offline after its existing dependency installation: its client-generation step compares freshly generated TypeScript against committed .NET output and compiles/exercises both. The full .NET regeneration is not added to default CI's network requirements.

### Provenance and review

The fixture references **Cratis.Arc.ProxyGenerator.Build 22.45.0** with an exact NuGet version range and a content hash in `DotNET/packages.lock.json`. The comparison resolves its `tasks/net10.0/Cratis.Arc.ProxyGenerator.Build.dll` executable from the fixture's restored assets. This is the executable shipped by the MSBuild package (normally invoked by the `CratisProxyGenerator` target), not a global tool, a hand-translated template, or a build of a neighboring Arc checkout. It receives the fixture assembly, a newly allocated scratch output directory, `0` namespace segments to skip, and `--exclude-namespace=HttpFixture*`. The exclusion limits generation to the paired namespace without altering the HTTP fixture. All remaining generator options use their defaults: `/api`, classes, extensionless imports, hooks and barrels, no proxy suffix. Its ordinary whole-output deletion only sees the new scratch directory.

`ProxyComparison/provenance.json` records both generator packages/versions and options. `Snapshots/DotNET/` and `Snapshots/TypeScript/` contain untouched captured outputs; `raw.diff` is their full unified byte diff, including original headers. Each run retains its new raw diff under `.ai-work/keep/proxy-comparison/`, plus the .NET generator log when invoked. Failed runs retain their generated scratch tree too.

For stable comparison, **only the timestamp in the first `// @generated by Cratis` line is replaced**. The header must have the expected syntax and a valid SHA-256 body hash. Source labels, hashes, whitespace, imports, comments, line endings and all other bytes remain checked. No formatter or semantic-equivalence comparison runs. Added/deleted files and a single changed body byte fail, even if they would compile identically.

Review `ProxyComparison/differences.json` alongside `raw.diff`. The intentional differences are:

- Blank lines, compact getters, and sorting-helper field/getter layout.
- Type-only imports, import ordering and merged Fundamentals imports. .NET output requires type-import elision, so the shared strict consumer does not enable `verbatimModuleSyntax`.
- The .NET command hook's `@ts-ignore`; TypeScript compiles without it.
- Read-model-only .NET query provenance versus method-qualified TypeScript provenance.
- **Sorting API:** .NET emits `sortBy.id` from the query parameter; TypeScript emits `name`, `detail`, `notice` and `status` from the result. The TypeScript result-oriented API is retained, not changed to copy this .NET behavior.
- **Enum API:** .NET emits `draft`/`published`; TypeScript preserves `Draft`/`Published`. Numeric wire values agree.
- TypeScript's owned-barrel provenance header; the .NET barrel has none.

`Notice.ts` agrees after timestamp normalization. Routes, parameter/property descriptors, GUID/date/nested/derived hydration, numeric enum values, portable validation boundaries/messages and all command/query/observable hook signatures are asserted against the pinned client. Runtime checks use controlled GET responses, not a live .NET server or a mounted React tree. Each output runs in a separate process so derived-type registration cannot leak from the other. A strict consumer includes negative type checks; bundling for the Node runtime resolves extensionless imports without modifying the captured sources.

After inspecting a deliberate change, update the inventory reasons, then run:

```sh
node ContractTests/ProxyComparison/compare.mjs --capture
yarn test:proxy-comparison
```

Capture requires actual .NET regeneration and passing compilation/behavior checks. It is an explicit review operation, never a test's automatic response to drift. Review and commit the changed snapshots, provenance and raw diff together. The TypeScript package version in provenance records the capture version; unrelated version bumps do not force recapture.

This comparison is a bounded instrument, not a universal byte-equality contract; see [decision 0001](../decisions/0001-keep-proxy-generation-focused-on-client-contracts.md). `Client/templates-source.test.mjs` separately verifies the Templates fixture's flat `Register.ts`, `All.ts`, `Listing.ts`, barrels, routes, deterministic metadata, server-handled-event omission and safe regeneration cleanup. That check runs in the same client-generation CI step.
